# Use Case: Generate Invoice

## Basic Information
- **Use Case ID**: UC-506
- **Primary Actor**: Frontdesk
- **Secondary Actors**: System, Customer, Waiter, Notification Service, Printer Service
- **Priority**: High
- **Status**: Draft
- **Trigger**: Frontdesk needs to generate and deliver invoice after bill request

## Flow of Events

### Preconditions
1. Frontdesk is authenticated and logged into the system
2. Bill request exists for a session (from UC-505)
3. Session is in billable state (Active with bill requested, or Ended but unpaid)
4. System is operational and accessible
5. Printer is connected and operational (for physical invoice)

### Postconditions
1. Invoice is generated and stored in the system
2. Physical invoice is printed for customer delivery
3. Waiter is notified to collect and deliver invoice
4. Session status may be updated (e.g., "Awaiting Payment")
5. Audit log records invoice generation event
6. Bill request notification is marked as processed

### Main Success Scenario

#### Invoice Generation Process
1. Frontdesk views dashboard and navigates to notifications/bill requests section
2. System displays pending bill requests with:
   - Table number and session ID
   - Time since request
   - Requestor (Customer/Waiter)
   - Current bill total
   - Session type (Buffet/À la carte)
3. Frontdesk selects a bill request to process
4. System validates:
   - Session exists and is unpaid
   - Session has at least one order (for à la carte) or customer count > 0 (for buffet)
   - Session is in billable state (not cancelled, not already paid)
   - All orders are in billable status (served or completed)
5. System directs to invoice generation interface
6. System displays invoice preview based on session type:

7. Frontdesk reviews invoice details and clicks "Generate Invoice"
8. System performs final validation and creates invoice record with:
   - Unique Invoice ID
   - Session reference
   - Itemized charges
   - Tax and service calculations
   - Final total
   - Generation timestamp
   - Generated by (staff ID)
9. System updates session status to "Awaiting Payment"
10. System sends invoice to printer with professional formatting
11. System notifies assigned waiter (or available waiters): 
    "Invoice ready for Table {X}. Please collect from frontdesk."
12. System marks original bill request as "Processed"
13. System displays success message: "Invoice generated and sent to printer"
14. Waiter collects printed invoice and delivers to customer

## Alternative Flows

### A1: Apply Discount or Adjustment
7a. Frontdesk clicks "Add Discount" before generating
8a. System shows discount options:
    - Percentage discount (5%, 10%, 15%, custom)
    - Fixed amount discount
    - Reason for discount (dropdown: loyalty, complaint, promotion, other)
9a. Frontdesk applies discount and reason
10a. System recalculates totals with discount applied
11a. Use case continues from step 7

### A2: Edit Invoice Details
7b. Frontdesk clicks "Edit" to modify charges
8b. System allows limited edits:
    - Remove disputed items (with reason)
    - Adjust quantities (with manager approval if needed)
    - Modify service charge (manager approval required)
9b. System tracks all modifications in audit trail
10b. Use case continues from step 7

### A3: Multiple Payment Methods
14a. Customer requests split payment
15a. Waiter informs frontdesk
16a. Frontdesk processes split payment (separate use case)
17a. System generates separate invoices for each payment portion

## Exception Flows

### E1: Printer Offline or Error
10b. System cannot print invoice
11b. System displays: "Printer error. Invoice generated but not printed."
12b. System provides options:
    - Retry printing
    - Save as PDF for email/display
    - Mark for manual printing later
13b. Frontdesk chooses alternative delivery method

### E2: Validation Failures
4c. System detects validation failure:
    - Session already paid
    - No billable orders
    - Session cancelled
5c. System displays specific error and prevents invoice generation
6c. Use case ends

### E3: System Calculation Error
8d. System detects calculation discrepancy
9d. System alerts frontdesk and suggests recalculation
10d. Frontdesk can override with manual calculation (requires manager approval)
11d. System logs the override and discrepancy

## Special Requirements
- **Calculation Accuracy**: Tax and service charges must calculate to 2 decimal places
- **Print Quality**: Invoice must print clearly with restaurant branding
- **Notification Speed**: Waiter notifications within 15 seconds
- **Data Integrity**: Invoice amounts must match session order totals
- **Audit Trail**: Complete record of all invoice modifications

## Business Rules

### Invoice Generation Rules
- **BR-INV-01**: Invoices can only be generated for unpaid, billable sessions
- **BR-INV-02**: À la carte sessions must have at least one served order
- **BR-INV-03**: Buffet sessions must have valid customer count and tier pricing
- **BR-INV-04**: All calculations must use current tax and service charge rates

### Pricing Rules
- **BR-INV-05**: Buffet pricing uses tier base price × customer count
- **BR-INV-06**: Extra charge items use menu pricing rules
- **BR-INV-07**: Tax calculations apply to subtotal + service charge
- **BR-INV-08**: Discounts require reason documentation

### Workflow Rules
- **BR-INV-09**: Invoice generation triggers waiter notification for physical delivery
- **BR-INV-10**: Printed invoices must include restaurant contact and tax information
- **BR-INV-11**: Digital invoice copies must be stored for 7 years
- **BR-INV-12**: Modifications to generated invoices require manager approval

## User Interface Requirements

### Invoice Preview Interface
- Clear distinction between à la carte and buffet formats
- Real-time calculation display
- Professional formatting matching final printed invoice
- Edit and discount controls with appropriate permissions
- Validation warnings for problematic items

### Printed Invoice Format
- Restaurant logo and contact information
- Itemized charges with clear descriptions
- Tax and service charge breakdown
- Invoice number and generation timestamp
- Payment instructions and methods accepted
- Thank you message and return invitation

### Notification Interface
- Clear alert for waiters about ready invoices
- Table number and invoice amount prominently displayed
- Option for waiters to acknowledge collection
- Time tracking for invoice delivery performance

## Integration Points
- **Session Management**: Validates session state and retrieves session data
- **Order Management**: Pulls order details and pricing for à la carte
- **Menu Management**: Provides buffet tier pricing and extra charge items
- **Payment System**: Prepares for payment processing after invoice delivery
- **Notification System**: Alerts waiters for physical invoice delivery
- **Print Service**: Handles physical invoice printing
- **Audit System**: Logs all invoice generation and modification events

## Data Fields

### Invoice Record
- Invoice ID (unique)
- Session ID reference
- Invoice type (À la carte/Buffet)
- Itemized charges
- Subtotal, taxes, service charges, discounts, total
- Generation timestamp
- Generated by staff ID
- Status (Generated, Paid, Cancelled)
- Print status

### Buffet Invoice Specific
- Buffet tier
- Customer count
- Base buffet charge
- Extra charge items breakdown

### À La Carte Invoice Specific
- Order items with quantities and prices
- Order timestamps and status
